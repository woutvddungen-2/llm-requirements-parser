INTERPRETATION RULES

1. Replacement / exception overrides:
   "ipv", "maar", "behalve", "niet ... maar ..." → later rule replaces earlier.

2. Scope restriction:
   "alleen", "uitsluitend" → applies ONLY to that group.

3. Inheritance:
   Inheritance is mandatory and field-specific.
   Subgroups inherit by copying the broader rule first, then applying only the explicitly stated change.
   "ook" adds properties.
   "in plaats van" replaces only the conflicting property and preserves the rest.
   
   Example:
   If all binnendeuren have kaartlezer, deurdranger and sluitplaat, and
   "De serverruimte krijgt een gezichtscanner in plaats van een kaartlezer",
   then serverruimte keeps deurdranger and sluitplaat and only reader_types changes.

4. Door logic:
There are two broad groups:
   - buitendeuren
   - binnendeuren

   hints:
   - voordeur, achterdeur, buitendeur, nooduitgang, uitgang, vluchtdeur are typically buitendeuren unless stated otherwise.
   - doors of indoor spaces such as serverruimte, directiekantoor, magazijn, kantoor and vergaderruimte are typically binnendeuren unless stated otherwise.

   Area-to-door interpretation:
   When an area or room is assigned door hardware, reader, lock, closer, exit or emergency properties, interpret this as applying to the doors of that area.

   Examples:
   - "De serverruimte krijgt een gezichtscanner" -> the doors of the serverruimte get a gezichtscanner
   - "Directiekantoren krijgen ook een pincodelezer" -> the doors of directiekantoren also get a pincodelezer

   Named areas such as serverruimte or directiekantoor are not broad door groups by themselves; only their doors inherit door properties.

5. Area splitting:
   If exceptions exist → split into:
   - specific subgroup
   - remaining group (e.g. "overige binnendeuren")
   When a subgroup is carved out of a broader group, always output:
   - the specific subgroup
   - the residual broader group using the canonical name "overige <groep>"

6. No overlap:
   door_rules areas must not overlap.

7. Do NOT infer:
   - No lock from door closer
   - No direction from reader type

8. Replacement
   Replacement is field-specific, not whole-rule replacement: "in plaats van" replaces only the conflicting field, all other inherited fields remain.

DOOR RESOLUTION

is_external flag:
- The `is_external` flag on each door is authoritative. Do not override it based on space names.
- `is_external: false` → binnendeur, always. Even if the space is named "Entree", "Lobby", or similar.
- `is_external: true` → buitendeur, always.
- When a requirement targets "alle binnendeuren", include every door with `is_external: false`.

door_id:
- When available_doors are provided, resolve each rule to a specific door and set `door_id`.
- Each rule targets exactly one door. When multiple doors match, emit one rule per door with the same fields.
- Do not omit `door_id` when the mapping is known.
- If no door in the list matches the requirement, still emit the rule using `areas` and `connects_to_areas` — do NOT suppress the rule. The door list may be incomplete.

areas with door_id:
- `areas` must always be set, even when `door_id` is set.
- Use the space name(s) from the requirement text that identify the door — not both sides from the door map.
- Example: "serverruimte krijgt een paslezer" → areas=["serverruimte"], even if the door also connects to "hal".

connects_to_areas:
- Only set when `door_id` cannot be resolved AND the text explicitly says "van X naar Y" (naming both spaces).
- NEVER set connects_to_areas when `door_id` is known — door_id already identifies the door uniquely.
- NEVER set connects_to_areas just because you know both sides from the door map.
- NEVER set connects_to_areas because one side is OUTSIDE — `areas` handles reader placement correctly.

Direction mapping for "van X naar Y":
- X is the source/unsafe side → put X in `connects_to_areas`
- Y is the protected/destination side → put Y in `areas`
- Example: "deur van Hal naar Serverruimte" → areas=["Serverruimte"], connects_to_areas=["Hal"]
- NEVER put the same space in both `areas` and `connects_to_areas`.
