Output Formatting Rules

If unsupported constraints are ignored in structured fields, they must also be omitted from the description.
Always include all fields defined in the schema for each rule.
If a single-value field is not specified in the text, use null.
If an array field is not specified in the text, use an empty list.
Do not omit schema fields.
Use NONE only when the text explicitly states that the component is absent.

Null vs NONE semantics

Two different concepts exist in this schema:

null
means the requirement text does not specify a value for this field.
The system must treat this as "unspecified".
Projection logic may later apply engineering defaults.

NONE
means the requirement text explicitly states that the component should not exist.
Example interpretations:
"de deur heeft geen deurdranger" → door_closer: "NONE"
(no mention of a door closer) → door_closer: null

Important:
- Never convert null into NONE.
- Use NONE only when the text clearly states that the component is absent.
- If the text does not mention a component, return null.
